C. Data Mining + Machine Learning

Data mining = process of extracting patterns from large datasets by combining statistics, artificial intelligence and database management. The results of data mining are models or patterns. The module sets up mathematical models using Bayesian inference, optimisation theory, collaborative filtering, cluster/pattern analysis, kernel methods and learning theory. Machine learning = ability to teach a computer without explicitly programming it. Some people regard data mining and machine learning as synonymous. ML works well when we do not know exactly what we are looking for. Example: we may not know in advance what makes someone like or dislike a film. ML may be less useful when the goal can be described directly. Lecture example: finding resumes on the web may be better handled with direct keyword/phrase rules.

F. Bonferroni principle

Bonferroni's principle is a warning against overzealous data mining. If we search enough random data, many patterns will look significant just by chance.
Exam sentence: before trusting a discovered pattern, estimate how many such patterns would occur in random data. If random hits are expected to be numerous, the discovery is likely bogus.

09.05.2026Lecture 1 - Bonferroni expansion

Bonferroni principle - fuller memorisable explanation

Bonferroni’s principle is about statistical limits of data mining. If a dataset is huge and we search for many possible patterns/events, some apparently unusual events will occur even if the data is random. These random occurrences are called bogus in the lecture: they have no real cause except chance. Informal rule: calculate the expected number of occurrences assuming random data. If this expected number is much larger than the number of real cases we hope to find, almost anything found is likely to be a statistical artefact.
Exam paragraph: Bonferroni tells us not to trust a discovered pattern only because it looks rare. In large-scale mining, we must compare the number of discovered events with the number expected by chance.

Total Information Awareness example

Lecture 1 uses the 2002 Total Information Awareness idea as motivation. The worry: if credit-card receipts, hotel records, travel records and many other activities are mined for terrorist-like behaviour, many innocent or irrelevant activities may match just by chance. The broader the search, the more false discoveries we should expect. The narrower and more carefully defined the event, the less likely the result is purely bogus.

Curse of dimensionality and fake correlations

Curse of dimensionality: as the number of variables/features increases, the number of unit cells in the data space grows exponentially. With many variables, there is a high probability of finding some variable X that correlates with Y even when there is no real relationship in the domain. This is the explanation behind the fake-correlation slides.
Exam trap: “high correlation” found after searching many variables is not automatically meaningful. It may be exactly what Bonferroni predicts under randomness.

09.05.2026Lecture 1 - labelled data, outliers, images

G. Tabular data, labelled and unlabelled

A dataset can be represented as a table: rows are instances and columns are attributes/features. Labelled data: one attribute is specially designated and the task is to predict it. Example: spam/not spam; object class in an image. Unlabelled data: there is no specially designated target attribute. Example: grouping customers by behaviour.

H. Outliers / anomalies

A dataset may contain objects that do not comply with the general model or behaviour of the data. These objects are called outliers or anomalies. Outliers may be noise, errors, rare events, or genuinely interesting abnormal behaviour. Outliers may be detected using statistical tests based on a probability model, or using distance measures where points far away from others are suspicious.

Data preparation

Lecture 1 stresses that real data often needs preparation before mining. Cleaning: remove noise, errors and inconsistencies. Transformation: put data into a suitable representation. Attribute reduction: reduce irrelevant/redundant features because too many features can worsen mining.

I. Lecture 1 supplement: images as data

Data preparation - details to remember

Data cleaning: real-world data can contain erroneous values from measurement errors, subjective judgements, malfunctioning equipment or misuse of recording equipment. Missing values: in many real-world datasets, values are not recorded for all attributes. Reducing attributes/features: too many irrelevant attributes create computational overhead and can make algorithms perform poorly. Feature reduction / dimension reduction: the general name for reducing the number of attributes before processing.
Exam sentence: more features are not automatically better; irrelevant features can increase computation and damage mining quality.

Image supplement - compact exam version

An ideal image is a two-dimensional light-intensity function f(x,y), where x and y are spatial coordinates and f(x,y) describes brightness or colour. A digital image represents the continuous image by a 2-D array of discrete samples. The amplitude of each sample is quantised into a finite number of bits. Each element of the array is a pixel or pel, meaning picture element. A grayscale digital image can be represented as an M by N matrix of intensity values. For a colour image, f may be one colour component, e.g. red, green or blue. Digital images are typically quantised to 256 grey levels; too few grey levels can cause visible contouring.
Memory sentence: image data becomes data mining input by turning visual information into numerical arrays/matrices.
