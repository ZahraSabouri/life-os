Persistence

● The programs we have seen so far are transient.

– They run for a short time and produce some output, but when they end,

their data disappears.

– If you run the program again, it starts with a clean slate. ● Other programs are persistent.

– They run for a long time. – They keep at least some of their data in permanent storage (a hard

drive, for example).

– If they shut down and restart, they pick up where they left off.

● A text file is a sequence of characters stored on a permanent medium like a

hard drive, flash memory, etcetera.

● Python’s built-in function open takes the name of the file as a parameter and

returns a file object you can use to read the file’s contents.

>>> fin = open( ’words.txt’ )

Reading a File

● The file object provides several methods for reading. ● readline reads characters from the file until it gets to a newline, and

returns the result as a string.

>>> fin.readline() ’a\n’

● The sequence \n represents the newline character that separates this line

from the next.

● The file object keeps track of where it is in the file, so if you call readline

again, you get the next line.

>>> fin.readline() ’aa\n’ >>> fin.readline() ’aah\n’

The readlines Method

● Unlike readline (which reads one line each time it is called), readlines reads

all lines in the file at once.

● readlines outputs a list, where each element of the list is a line from the

file.

>>> fin = open( ’words.txt’ ) >>> lines = fin.readlines() >>> len( lines ) 3 >>> lines

[’a\n’, ’aa\n’, ’aah\n’]

● You can also use a file object as part of a for loop. ● The string method strip() returns a copy of the string with both leading

and trailing characters removed (by default, it removes whitespaces).

● We can also use Python’s with statement to open the file.

– Code within its indented block will be run when the file is open. – We do not need to call close; when the indented block ends, Python will

automatically close the file.

with open( ’words.txt’ ) as fin:

contents = fin.read() print( contents )

● To write a file, you have to pass open the mode ’w’ as a second parameter. ● If the file already exists, opening it in write mode clears out the old data and

starts afresh.

● If the file doesn’t exist, a new one is created.

● The write method puts data into the file. ● The return value is the number of characters that were written.

>>> line1 = "Alan M. Turing was an English mathematician,\n" >>> fout.write( line1 ) 45

● The file object keeps track of where it is, so if you call write again, it adds

the new data to the end of the file.

>>> line2 = "computer scientist, logician, cryptanalyst,\n" >>> fout.write( line2 ) 44

● Files should be closed at the end. ● All files are automatically closed when the program ends.

The writelines Method

● Like readlines, the writelines method can be used to write a list of

strings to the file.

● Each string in the list may of course be a line.

>>> lines = [ ’a\n’, ’aa\n’, ’aah\n’ ] >>> fout = open( ’words.txt’, ’w’ ) >>> fout.writelines( lines ) >>> fout.close()

>>> fin = open( ’words.txt’ ) >>> lines2 = fin.readlines() >>> lines2

[’a\n’, ’aa\n’, ’aah\n’]

open Modes

● The open method accepts several different modes (we’ve seen ’w’):

r read Opens the file for reading only
w write Opens the file for writing
a append Like ’w’, but all write() calls will append to an existing file
a+ append + Opens the file for writing and reading. Places the file pointer at the end of an existing file
r+ read + Opens the file for reading and writing. Places the file pointer at the beginning of the file.
w+ write + Opens the file for reading and writing. Any existing content is cleared. Places the file pointer at the beginning of the file.

The File Pointer

● We can keep track of where we are within a file (once open) using tell.

For example, if we have already read nine characters from the beginning:

>>> fin.tell() 9

● We can move to a specific position within a file using seek.

For example, if we wish to return to the third character from the beginning:

>>> fin.seek( 3 ) 9

● Subsequent read or write calls will operate from our current position

within the file.

● write accepts a string as its argument. ● A value can be converted to string using the str function. ● Alternatively, the format operator % can be used.

● The first operand is the format string, which contains one or more format

sequences.

● The second operand contains the values to be converted. ● The result is a string.

%d Decimal integer
%g Floating-point number, 2 d.p.
%s String
%x Hex value
%f Floating-point
%u Unsigned integer (non-negative)

>>> camels = 42 >>> ’%d’ % camels ’42’

● A format sequence can appear anywhere in the string.

>>> ’I have spotted %d camels.’ % camels ’I have spotted 42 camels.’

● If there is more than one format sequence in the string, the second argument

has to be a tuple.

● Each format sequence is matched with one element of the tuple, in order.

>>> ’In %d years I have spotted %g %s.’ % ( 3, 0.1, ’camels’ ) ’In 3 years I have spotted 0.1 camels.’

● The number of elements in the tuple has to match the number of format

sequences in the string.

● Also, the type of each element has to match its respective format sequence.

>>> ’%d %d %d’ % ( 1, 2 ) TypeError: not enough arguments for format string >>> ’%d’ % ’dollars’ TypeError: %d format: a number is required, not str

Formatting Strings

● A more powerful alternative is the string format method. ● str.format is a simple position-based formatting method which uses {} as a

placeholder.

"Happy {}, {}".format( ’New Year’, ’Tom’ )

Formatting Strings

● It is possible to give a place holder an explicit positional index:

"Happy {0}, {1}".format( ’New Year’, ’Tom’ )

● You may like to re-arrange the order of the displaying items:

"Happy {1}, {0}".format( ’Tom’, ’New Year’ )

● Or use variable names to match items with their positions (offering increased

readability of the code):

"Happy {season}, {name}".format( season=’New Year’, name=’Tom’ )

● Files are organized into directories (also called “folders”). ● Every running program has a “current directory”, which is the default

directory for most operations.

● For example, when a file is opened for reading, Python looks for it in the

current directory.

The os Module

● The os module provides functions for working with files and directories. ● “os” stands for “operating system”. ● os.getcwd returns the name of the current directory. ● “cwd” stands for “current working directory”.

>>> import os >>> cwd = os.getcwd() >>> cwd ’/home/dave

● A string like ’/home/dave’ that identifies a file or directory is called a path. ● A simple filename, like ’words.txt’ is also considered a path, but it is a relative

path because it relates to the current directory.

● If the current directory is ’/home/dave’, the filename ’words.txt’ would refer

to ’/home/dave/words.txt’.

● A path that begins with / (Unix), or a drive letter (e.g. “C:\”, on Windows),

does not depend on the current directory. ● It is called an absolute path. ● os.path.abspath provides the absolute path to a file.

>>> os.path.abspath( ’words.txt’ ) ’/home/dave/words.txt’

● os.path.exists checks whether a file or directory exists.

>>> os.path.exists( ’words.txt’ ) True

● os.path.isdir checks whether the path is a directory.

>>> os.path.isdir( ’words.txt’ ) False >>> os.path.isdir( ’/home/dave’ ) True

● os.path.isfile checks whether the path is a file.

>>> os.path.isfile( ’words.txt’ ) True >>> os.path.isfile( ’/home/dave’ ) False

os.chdir Function

● os.chdir accepts a string path, and changes the program’s current working

directory to that path.

>>> os.getcwd() ’/home/dave’ >>> os.chdir( ’/home/dave/python_code’ ) >>> os.getcwd() ’/home/dave/python_code’

● os.listdir returns a list of the files (and other directories) in the given

directory.

>>> os.listdir( cwd )

[ ’music’, ’photos’, ’words.txt’ ]

Walking through a Directory

● The following example “walks” through a directory, prints the names of all

the files, and calls itself recursively on all the sub-directories.

● os.path.join takes a directory and a file name and joins them into a

complete path.

● [the os module provides a function called walk that is similar to this one but

more versatile.]

def walk( dirname ):

for name in os.listdir( dirname ):

path = os.path.join( dirname, name ) if os.path.isfile( path ):

print( path ) else:

walk( path )

● Note that we’re not covering recursion, but a recursive function is one which can call itself

(known as the “recursive step”), but can also return a value (known as the “base case”, a condition which leads to all the function calls returning, and the function ending).

IO Errors

● Many things can go wrong when working with files.

– Opening a file that doesn’t exist results in an IOError. – Attempting to open a file without permission results in a PermissionError. – Opening a directory for reading results in an IsADirectoryError.

● Functions like os.path.exists and os.path.isfile could be used. >>> fin = open( ’bad_file’ )

IOError: [Errno 2] No such file or directory: ’bad_file’ >>> fout = open( ’/root/new_file’, ’w’ ) PermissionError: [Errno 13] Permission denied: ’/root/new_file’ >>> fin = open( ’/home’ ) IsADirectoryError: [Errno 21] Is a directory: ’/home’

Catching Exceptions

● The try statement attempts to execute a code block. ● If that block fails, the except statement executes a second code block, designed

to handle the problem.

● Handling an exception with an except statement is called catching an

exception.

● Catching an exception gives a chance to fix the problem, or try again, or at

least end the program gracefully.

try:

fin = open( ’bad_file’ ) except:

print( ’Something went wrong.’ )

Catching Exceptions

try:

fin = open( ’bad_file’ ) except:

print( ’Something went wrong.’ )

● Python starts by executing the try clause, running the code within its block. ● If all goes well, it skips the except clause, and the program proceeds. ● If an exception occurs, it jumps out of the try clause and executes the

except clause, running the code within that block instead.

Pickling

● Pickling allows us to store objects, including complex data structures. ● Objects are stored sequentially. ● The pickle module can be used to:

– Translate (almost) any type of object into a string, and then back into an

object again.

– Store complex objects in binary files.

pickle.dumps Method

● pickle.dumps takes an object as a parameter and returns a string

representation.

● “Dumps” is short for “dump string”.

>>> import pickle >>> t = [ 1, 2, 3 ] >>> pickle.dumps( t ) b’\x80\x03]q\x00(K\x01K\x02K\x03e.

pickle.loads Method

● pickle.loads reconstitutes a pickled object. ● “Loads” is short for “load string”.

>>> t1 = [ 1, 2, 3 ] >>> s = pickle.dumps( t1 ) >>> t2 = pickle.loads( s ) >>> t2

[1, 2, 3]

Storing into Binary Files

import pickle farm_animals = [ "Cow", "Chicken", "Sheep", "Horse", "Duck" ] Pets = [ "Dog", "Cat", "Rabbit", "Hamster" ]

f = open( "animals.dat", "wb" ) # Opening binary file for writing pickle.dump( farm_animals, f ) pickle.dump( pets, f )

f.close()

f = open( "animals.dat", "rb" ) # Opening binary file for reading farm_animals = pickle.load( f ) pets = pickle.load( f ) print( farm_animals ) print( pets ) f.close()

Binary Files

● A binary file contains data which is stored in bits; it is usually read and written

in bytes (a group of 8 bits).

● Although a text file is intended to be human-readable, a binary file is not.

Binary Files

● A pickled object must be stored in a binary file. ● We can tell Python to treat files as binary by passing a dffierent mode string

as the second argument to open.

– “rb” opens a binary file for reading. – “wb” opens a binary file for writing.

● Note that the character ”b” can be added to any mode string (e.g. ”ab”, ”wb+”

etc.) to instruct open to use binary mode.

● Note also that a string read in binary mode will be a bytestring (e.g. b’data’

instead of ‘data’).

pickle.dump Method

● pickle.dump stores an object to a file in a binary format. ● Objects are stored sequentially.

– The file will contain the objects in First-in First-out (FIFO) order.

>>> f = open( "animals.dat", "wb" ) >>> pickle.dump( farm_animals, f ) >>> pickle.dump( pets, f ) >>> f.close()

pickle.load Method

● pickle.load loads an object from a binary file. ● Objects are retrieved sequentially.

>>> f = open( "animals.dat", "rb" ) # Opening binary file for reading >>> farm_animals = pickle.load( f ) >>> pets = pickle.load( f ) >>> f.close()

Shelving

● Shelving allows to store objects into a dictionary-like object which is saved

in a file.

● This allows Random Access to any of the stored objects.

The shelve Module

● The shelve module needs to be imported. ● shelve.open creates a shelf object. ● The shefl object works exactly like a dictionary, with the only exception that

the keys have to be strings.

● shelf.sync synchronizes the data and the file (which writes any yet

unwritten data to the file).

Storing Objects in a Shelf

import shelve shelf = shelve.open( "animal2.dat" )

# Opening file

# Storing objects in shelf shelf[ "farm_animals" ] = [ "Cow", "Chicken", "Sheep", "Horse", "Duck" ] shelf[ "pets" ] = [ "Dog", "Cat", "Rabbit", "Hamster" ] shelf[ "garden_animals" ] = [ "Bee", "Butterfly", "Worm", "Ant", "Bird" ] shelf.sync() # Synchronizing shelf.close() # Closing file

Retrieving Objects from a Shelf

import shelve shelf = shelve.open( "animal2.dat" )

# Opening file

# Retrieving objects from shelf print( ’Farm animals: {}’.format( shelf[ ’farm_animals’ ] ) ) print( ’Pets: {}’.format( shelf[ ’pets’ ] ) ) print( ’Garden animals: {}’.format( shelf[ ’garden_animals’ ] ) ) shelf.close() # Closing file

● Any file that contains Python code can be imported as a module. ● For example, a file named lc.py contains the following code:

return count

print( linecount( ’lc.py’ ) )

Writing Modules

● If the program is imported:

– It reads itself and prints the number of lines in the file; – It creates a module object lc. – It provides the function linecount.

>>> import lc 7 >>> lc <module ’lc’ from ’lc.py’> >>> lc.linecount( ’lc.py’ ) 7

● When the module is imported, the test code at the bottom is run. ● This can be avoided by changing the code as follows:

return count

if __name__ == ’__main__’:

print( linecount( ’lc.py’ ) )

The __main__ Variable

● __name__ is a built-in variable that is set when the program starts.

– If the program is running as a script, __name__ has the value

’__main__’. In this case, the code in the if clause is run.

– If the module is being imported, the value of __name__ is the name of the

module ( ’lc’ ). In this case, the code in the if clause is skipped.
