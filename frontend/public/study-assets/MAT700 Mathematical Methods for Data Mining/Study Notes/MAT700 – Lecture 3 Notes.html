10.05.2026Lecture 3 - 1. finding similar items

1. Finding Similar Items

The Lecture 3 problem is: given a large collection of objects, find pairs or groups that are similar. Examples in the lecture include near-duplicate Web pages, plagiarised documents, repeated news articles, similar customers, and similar products.
Lecture flow: object/document → set representation → Jaccard similarity → shingling for documents → signatures/minhashing for large-scale approximation.

Why this is a data-mining problem

Exact comparison of every pair is too expensive when the collection is huge. The aim is to keep the important similarity signal while avoiding quadratic-scale direct comparison where possible. The lecturer’s transcript emphasises the practical big-data tradeoff: allow a small error to get a much faster approximation.

Core exam sentence

Lecture 3 studies how to find similar items in large datasets by representing items as sets, measuring overlap using Jaccard similarity, and then compressing large sets into signatures using minhashing so similarity can be estimated efficiently.
10.05.2026Lecture 3 - 2. Jaccard similarity of sets

2. Jaccard Similarity of Sets

The lecture first turns similarity into a set problem: find sets with a relatively large intersection.
Definition
Common elements divided by elements appearing in either set.
Union shortcut
Useful under exam time pressure.
Range
1 means equal sets; 0 means disjoint sets.

Exam-ready wording

Definition question: The Jaccard similarity of two sets S and T is the ratio of the size of their intersection to the size of their union. It measures the relative overlap between the two sets.
Application question: To compare two documents or items, represent each one as a set of features. If the items are similar, the corresponding sets should have a large intersection. Jaccard similarity measures this overlap relative to the union.

Properties to memorise

It is symmetric: SIM(S,T)=SIM(T,S). Repeated elements do not matter for ordinary sets. Do not divide by the size of the larger set; the denominator is the union.

10.05.2026Lecture 3 - 3. textually similar documents

3. Textually Similar Documents

Lecture 3 applies Jaccard similarity to finding textually similar documents in a large corpus such as the Web or news articles.

Important distinction: textual similarity vs meaning

In this lecture, similarity means lexical, textual, or character-level similarity, not necessarily semantic similarity.
So if two documents use similar wording, copied phrases, or repeated sentences, Jaccard-style methods can help. If two documents express the same idea using completely different words, this lecture is not mainly about detecting that.

Document examples in lecture order

Plagiarism
A plagiarised text may copy substantial parts, alter a few words, or reorder sentences. Character-by-character equality is too strict.
Mirror pages
Popular Web pages may be duplicated across hosts. They are similar but often not identical because host and formatting information differ.
News articles from same source
Many newspapers may publish versions of the same article. News aggregators want to show one representative version rather than many near-duplicates.
Search-engine result quality
Search engines produce better first-page results when they avoid showing nearly identical pages.

Exam sentence

Jaccard similarity is useful for near-duplicate document detection because shared phrases or sentences produce many common features after the document is represented as a set.
10.05.2026Lecture 3 - 4. collaborative filtering

4. Collaborative Filtering

The lecture next gives collaborative filtering as another application of similar sets.

Definition

Collaborative filtering is a recommendation method where we recommend items to a user based on items liked by other users with similar behaviour or taste.

Amazon-style wording

A customer can be represented by the set of items they purchased. Two customers are similar if these sets have high Jaccard similarity. Similarly, an item can be represented by the set of customers who bought it, and two items are similar if their purchaser sets have high Jaccard similarity.

Important lecture nuance

Jaccard similarities need not be very high to be significant in huge sparse purchase/rating data. For Amazon-style data, two science-fiction customers may buy different books, so clustering similar books can make customer similarity stronger.

Netflix / rating-data wording

For rating data, ordinary sets lose information because they record only whether an item was watched or purchased, not how strongly it was liked. To include ratings, we can use bags: if a user rates a movie n stars, include that movie n times in the bag.

5. Jaccard Similarity for Bags

A bag, or multiset, allows repeated elements. Lecture 3 uses bags for rating data, where multiplicity can represent strength of preference.
MAT700 bag Jaccard definition
Numerator = common multiplicities. Denominator = sum of the two bag sizes.
Very important: in this lecture, the “union” size for two bags is the sum of the sizes of the two bags. Do not use the ordinary set formula for bags.

10.05.2026Lecture 3 - 6. shingling documents

6. Shingling Documents

Shingling is the lecture’s method for turning documents into sets.
k-shingle
A document is treated as a string of characters.
Shingle set
Appearing twice still counts once because this is a set.

Lecture example

If D = abcdabd and k=2, the 2-shingles are ab, bc, cd, da, ab, bd. As a set: . The shingle ab appears twice in the string but once in the set.

Why shingling works

Documents that share phrases or sentences share many shingles. If sentences appear in different orders, many local shingles can still be shared. If a few words are changed, many neighbouring shingles remain.

Whitespace rule

The lecture says it is sensible to replace any sequence of one or more whitespace characters by a single blank before forming shingles.
Do not confuse: bags are used for rating data above. For document shingling in this lecture, we use sets of shingles, not bags of shingles.
10.05.2026Lecture 3 - 7. choosing k

7. Choosing the Shingle Size k

The lecture rule is: k should be large enough that the probability of any given shingle appearing in any given document is low.
If k is too small
Unrelated documents share many common shingles by accident.
If k is too large
Genuinely similar documents may not share enough shingles.

Email example

If emails used only 26 letters plus a whitespace character, there would be 27 possible characters.
Possible k-shingles
A = number of possible characters.
Lecture email count
This supports k=5 for ordinary emails.

Rule-of-thumb correction

The lecture warns that characters are not equally likely. Common letters and blanks dominate, while rare letters such as z appear much less often.
Effective-character rule of thumb
Use this rougher mental model because real characters are not equally likely.
For large documents such as research articles, the lecture says k=9 is considered safe.
10.05.2026Lecture 3 - 8. signatures and characteristic matrix

8. Similarity-Preserving Signatures

Sets of shingles can be very large. With millions of documents, storing every shingle set or comparing every pair may be infeasible.
Goal: replace each large set by a much smaller signature, while still being able to estimate the Jaccard similarity of the original sets from the signatures alone.

9. Characteristic Matrix

10. Minhashing and the Minhash Theorem

Minhashing compresses a set while preserving information about Jaccard similarity.
Minhash definition
Permute rows, scan from top, record the first row where the set has membership 1.

Lecture example

Using the row order b, e, a, d, c for the characteristic matrix above:

Minhash theorem

Key theorem
For a random row permutation, the probability of equal minhash values equals Jaccard similarity.
10.05.2026Lecture 3 - minhash proof and signatures

10a. Why the Minhash Theorem Works

For two columns S and T, divide rows into three types:
TypePatternMeaning
X(1,1)row belongs to both sets
Y(1,0) or (0,1)row belongs to exactly one set
Z(0,0)row belongs to neither set
Jaccard in X/Y terms
Probability of equal minhash
Rows of type Z do not affect the first row where either column has a 1. The first relevant row among X and Y is equally likely to be any such row. The minhashes agree exactly when that first relevant row is type X.

11. Minhash Signatures

A single minhash is noisy, so the lecture uses many random row permutations.
Signature of set S
Usually represented as a column in the signature matrix.
Estimate similarity from signatures
The signature matrix has the same number of columns as the characteristic matrix but only n rows, one row for each minhash function.
Trap: minhash signatures estimate Jaccard similarity. They do not give exact similarity unless the signatures are effectively complete.

10.05.2026Lecture 3 - exam summary

13. Exam-Ready Summary

Must know, in lecture order

  1. Similar-items problem: find near-duplicate or similar objects in a huge collection.
  2. Jaccard similarity for sets: intersection divided by union.
  3. Lecture 3 document similarity is textual/character-level, not deep semantic similarity.
  4. Collaborative filtering: similar users/items by similar purchase/rating sets.
  5. Jaccard similarity for bags: sum of minimum multiplicities divided by |B|+|C|.
  6. Bag Jaccard is at most 1/2 under the MAT700 convention.
  7. k-shingle: substring of length k; shingle set contains shingles appearing at least once.
  8. Choose k large enough to avoid accidental matches, but not so large that genuine similarity disappears.
  9. Characteristic matrix: rows are universal elements, columns are sets, entries are membership indicators.
  10. Minhash: first row in a random permutation where a column has 1.
  11. Minhash theorem: probability of equal minhash values equals Jaccard similarity.
  12. Signature: vector of many minhash values; estimate similarity by fraction of matching positions.
  13. Jaccard distance bridge: dJ=1−SIM and the triangle inequality can be proved using minhash events.

Common mistakes

1. Using ordinary set Jaccard for bag questions.
2. Forgetting the MAT700 bag denominator is |B|+|C|, not ordinary union size.
3. Counting repeated shingles twice, although Lecture 3 uses shingle sets.
4. Saying Lecture 3 detects semantic similarity. It mainly detects textual similarity.
5. Saying minhash gives exact similarity. It estimates similarity from signatures.
6. Mixing Jaccard similarity and Jaccard distance.
